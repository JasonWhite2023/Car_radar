## 0. 摘要

本项目把厂家基于 ACX750 的 OV5640 DVP → DDR3 → HDMI 参考工程，移植到 BX72（XC7A100T-FGG484-2），显示改为 800×480，摄像头初始化改为 800×480 RGB565。

移植后图像能出，但一直存在两个问题：

1. **整体发灰、不鲜艳、暗部灰、盖镜头也灰**；
2. 早期还出现过**频闪/彩色圆环**（已通过回退 BLC + 修 Bayer 相位 + 关 LENC 基本解决）。

已做的排查覆盖了 BLC、AWB、SDE、CMX、LENC、曝光、IR-cut、显示器、裸 sensor、两个同厂商模组等。结论是：

- **数字/ISP/显示通路没问题**（PRE-ISP 彩条颜色正常、黑正常）；
- **偏置在 sensor 模拟/ADC/BLC**，BLC 能调的位基本试完，仍未修好；
- **两个同厂商模组表现一样**，已下单另一个厂商的模组做对比；
- 颜色映射（Bayer）和圆形炫光（LENC）已经有有效修复，但**整体灰/低饱和**仍在。

## 1. 项目与硬件

### 1.1 目标

- OV5640 DVP 摄像头 → DDR3 帧缓冲 → HDMI 800×480 实时显示；
- 摄像头 800×480 RGB565；
- 显示 800×480，33 MHz 像素时钟。

### 1.2 硬件

| 项目 | 参数 |
|---|---|
| FPGA | XC7A100T-FGG484-2（BX72） |
| 系统时钟 | 50 MHz，`Y18` |
| 复位 | `V17`（KEY2，低有效） |
| HDMI | `W19`(clk_p)、`Y21/W21/U22`(dat_p[0:2])、`AA21`(oe) |
| VGA（保留不用） | `disp_hs=E13`、`disp_vs=E14`、`disp_clk=A19` |
| DDR3 | 板载 2× MT41K256M16（32 位），工程只用低 16 位（DQ0~15） |
| 摄像头 | OV5640，DVP 8 位，模块自带 24 MHz 晶振，无 XCLK |
| 镜头 | **广角镜头**，固定焦距（无 AF），可手动旋转对焦 |
| 显示 | 800×480，33 MHz（`dvi_pll` 100→33/165 MHz），1056×525 |

摄像头引脚（`io.xdc`）：

| 信号 | 引脚 |
|---|---|
| `camera_pclk` | B21 |
| `camera_data[0..7]` | C19 / D22 / E22 / D21 / E21 / B22 / C22 / A21 |
| `camera_href` | G22 |
| `camera_vsync` | U21 |
| `camera_sclk` | T21 |
| `camera_sdat` | G21 |
| `camera_rst_n` | C18（**当前注释未用**） |

### 1.3 数据流与时钟

```
OV5640 DVP (RGB565, 16 bit)
  → DVP_Capture (16 bit RGB565)
  → wr_ddr3_fifo (16 → 128)
  → MIG 7-series AXI (16 bit DDR3)
  → DDR3
  → rd_ddr3_fifo (128 → 16)
  → disp_data 24 bit (RGB565 零扩展: {R5,000,G6,00,B5,000})
  → disp_driver (800×480)
  → dvi_encoder (TMDS)
  → HDMI
```

| 时钟 | 来源 | 频率 |
|---|---|---|
| `clk50m` | 板载 `Y18` | 50 MHz |
| `loc_clk50m` | `pll` clk_out1 | 50 MHz |
| `loc_clk100m` | `pll` clk_out3 | 100 MHz（给 `dvi_pll`） |
| `loc_clk200m` | `pll` clk_out2 | 200 MHz（MIG 参考） |
| `pixelclk` | `dvi_pll` clk_out1 | 33 MHz |
| `pixelclk5x` | `dvi_pll` clk_out2 | 165 MHz |
| `camera_pclk` | 摄像头 `B21` → BUFG | 约 45.6 MHz |

帧缓冲大小：`800*480*2-1 = 767999`（0xBB7FF），约 750 KB。

## 2. “标准程序”是什么

这里把三份“标准”分开：

### 2.1 厂家参考工程（ch43 的 16bit 版本）

`D:\Xilinx\FPGAProject\ch43_acx750_ov5640_ddr3_hdmi\acx750_ov5640_ddr3_hdmi_16bit`

- 板卡：ACX750；
- 摄像头：OV5640 **1280×720**（`0x3035=0x21`、`0x3036=0x69`、HTS=0x0764、VTS=0x02E4）；
- 摄像头 XCLK：由 FPGA 的 PLL 提供 24 MHz（`clk_out4`）；
- 显示：1280×720，`dvi_pll` 74.25 MHz；
- 初始化：`0x5001=0x83`（scale off）、`0x5584=0x10`、BLC 原始（`0x4001/0x4004=0x02`、`0x4005=0x1A`、目标默认 0x10）；
- DDR3：16 位。

### 2.2 手册 4.1.3 的 800×480

OV5640 应用指南 4.1.3 给出的 800×480 参考值：

- `0x3035=0x41`、`0x3036=0x72`、`0x3803=0xBE`、`0x3807=0xE4`、`0x380D=0x69`、`0x380E=0x03`、`0x380F=0x21`、`0x3813=0x06`、`0x3A02=0x09`、`0x3A03=0x63`、`0x3A14=0x09`、`0x3A15=0x63`、`0x4837=0x22`、`0x3824=0x02`、`0x5001=0xA3`（scale on）。

### 2.3 本项目基线（`c992e09`）

= 厂家参考 + 移植到 BX72 + 800×480 + 手动 496 行曝光，但**还没做 BLC/颜色实验**：

- 800×480 那 19 个寄存器；
- BLC 原始（`0x4001/0x4004=0x02`、`0x4005=0x1A`、`0x4009` 默认、`0x4000` 默认）；
- `0x3821=0x07`、`0x5000=0xA7`、`0x5001=0xA3`、`0x5584=0x10`；
- 手动曝光 `0x3503=0x03`、`0x3501=0x1F`、`0x3502=0x00`（496 行）。

## 5. 有效 / 无效 / 未定

### 5.1 有效

1. **手动 496 行曝光**：让画面从“几乎全灰/看不见”变成可见；自动曝光之前是欠曝。
2. **Bayer 相位 `0x3821=0x01`**：修正了红/绿/蓝映射（G 主导的偏色），色调基本准。**只对当前广角模组有效；换新模组可能需要 `0x07`。**
3. **LENC off `0x5000=0x27`**：圆形炫光/彩色牛顿环消失。**只对当前广角镜头有效；新模组可先恢复 LENC on。**
4. **整体回退 BLC**：频闪消失，画面稳定（但灰）。
5. **`0x503D=0x00`**：清理测试图案，避免黑图/彩条遗留。

### 5.2 无效

1. **BLC 重校准**（目标 0、黑线 0/8、redo、format、freeze、`0x4000=0x8D`）：盖镜头仍灰；“盖镜头更黑”是频闪暗相造成的错觉。
2. **AWB off**：品红会变，但饱和度仍低；不是 AWB。
3. **SDE off**：饱和度/对比度无变化；不是 SDE。
4. **CMX off**：变灰 + 绿色炫光；不是 CCM。
5. **SDE UV/contrast**：略有变化，但不解决“整体灰”。
6. **IR-cut/NIR**：铝罐遮住仍灰；不是 NIR。
7. **显示器**：FPGA 彩条黑正常；不是显示器。
8. **镜头/LENC 对“灰”**：裸 sensor 也灰；镜头不是灰的主因。
9. **两个同厂商模组**：结果一样，不是单颗模组偶发。

### 5.3 未定/待验证

1. **新厂商模组**：盖镜头黑不黑、颜色正不正常；
2. **供电**：模组 3.3 V、纹波、摄像头座子；
3. **PCLK/时序**：45.6 MHz、DVP 采样；
4. **720p 原始表**：换回厂家 720p 做对照；
5. **CCM/曝光**：低饱和是否来自 CCM 或过曝；
6. **800×480 scaler**：缩放带来的软/灰。

---

## 6. 当前结论

1. **数字/ISP/显示通路正常**：PRE-ISP 彩条颜色正确、黑正确；问题在 **sensor 模拟/ADC/BLC**。
2. **BLC 可调项基本试完**（目标、黑线、redo、format、freeze、apply2blackline），盖镜头仍灰 → 偏置不在 BLC 可控范围，或 sensor 模拟/ADC 本身。
3. **两个同厂商模组一样** → 更像**初始化表/同一批模组**，而不是单颗损坏。
4. **颜色映射已修好**（`0x3821=0x01`），**圆形炫光已修好**（LENC off），但**整体灰/低饱和**仍在。
5. **AWB/SDE/CMX 都不是主因**；低饱和更可能在 **CCM/曝光/镜头**。

1. 先恢复 LENC on（原厂镜头匹配原厂 LENC）；

1. **供电**：量模组 VCC 3.3 V、纹波、摄像头座子；
2. **720p 原始表**：换回厂家 720p 做对照；

## 10. 白平衡设置与发粉修复（2026-10-25）

### 10.1 当前白平衡

- **AWB 开**：`0x5001=0x23` 的 bit0=1；
- **AWB 模式**：`0x3406` 没写 → 芯片默认 `0x00`（auto）；
- **初始增益**：`0x3400~0x3405` 没写 → 芯片默认：
  - R = `0x0410`（1040）
  - G = `0x0400`（1024）
  - **B = `0x0840`（2112）** ← 蓝增益约为 R/G 的 2 倍 → 偏蓝/品红
- **AWB 控制**：`0x5180=0xFF`、`0x5181=0xF2`、`0x5182=0x00`、`0x5190=0x46`（厂家值）。

### 10.2 发粉的原因

- B 增益默认 `0x0840`，是 R/G 的约 2 倍 → 如果 AWB 没有把它压下来，画面就偏蓝/品红（粉）；
- AWB auto 应该会调整，但在大面积单色/某种灯光下可能收敛慢或偏；
- 另外 CCM（`0x5381~0x538B`）也会影响粉/绿。

### 10.3 本轮修改

- `0x3406=0x01`（AWB 手动，固定增益）；
- `0x3404=0x04`、`0x3405=0x00` → **B = 0x0400（1024）**，与 G 相同；
- R/G 保持默认 `0x0410/0x0400`；
- `0x5001=0x23`（AWB 块仍开，但增益手动）。

### 10.4 测试

- 发粉是否减轻/消失；
- 白纸/白屏是否中性；
- 颜色是否更接近手机。

### 10.5 如果仍粉

- `0x5001=0x22`（AWB 块关）+ 上面的手动增益；
- CCM：`0x5001=0xA1`（关 CMX）对比；
- 标准 CCM/厂家表；
- 灯光（荧光灯偏绿，AWB 会往品红拉）。

### 10.6 如果偏绿

- 说明 G 相对 R/B 太强（B 从 `0x0840` 降到 `0x0400` 后，绿显出来了）；
- **方案 A：降 G** —— `0x3402=0x03`、`0x3403=0x80`（G=`0x0380`，比 R/B 低约 12%）；
- **方案 B：升 R/B** —— `0x3400=0x04`、`0x3401=0x80`（R=`0x0480`）、`0x3404=0x04`、`0x3405=0x80`（B=`0x0480`）；
- **方案 C：恢复 AWB 自动**（`0x3406=0x00`），让 AWB 自己加品红；
- **方案 D：CCM**（`0x5381~0x538B`）或灯光（荧光灯偏绿）。

本轮先做方案 A：G=`0x0380`。

### 10.7 白平衡参数与调法（2026-10-25）

| 寄存器 | 含义 |
|---|---|
| `0x5001` bit0 | AWB 块使能 |
| `0x3406` bit0 | 0=自动，1=手动固定 |
| `0x3400/0x3401` | R 增益（12 位：`0x3400[3:0]` 高 4 位，`0x3401` 低 8 位） |
| `0x3402/0x3403` | G 增益 |
| `0x3404/0x3405` | B 增益 |
| `0x5180~0x519E` | AWB 自动算法的控制 |
| `0x5381~0x538B` | CCM 颜色矩阵（也会影响绿） |
| `0x5580~0x5588` | SDE 饱和度/UV（不是白平衡） |

- 增益 = 值 / 1024：`0x400`=1.0x，`0x380`=0.875x，`0x340`=0.8125x；
- 绿/品红轴：G 相对 R+B；绿 → 降 G 或升 R+B；品红 → 升 G 或降 R+B；
- 粉/蓝轴：R 对 B；偏蓝 → 降 B；偏红 → 降 R；
- 每次步进 `0x10`（约 1.5%）。

当前（手动）：R=`0x0410`（1.016x）、G=`0x0340`（0.8125x）、B=`0x0400`（1.0x）。

调法：

1. 白纸/白屏，同一光源；
2. 偏绿 → `0x3403` 降（`0x20`/`0x00`）或 `0x3401/0x3405` 升；
3. 偏粉 → 反向；
4. 偏蓝 → `0x3405` 降；偏红 → `0x3401` 降；
5. 自动：`0x3406=0x00`；
6. 仍绿 → CCM（`0x5381`）/灯光（荧光灯偏绿）。

## 11. 图像左右翻转（`0x3821`）

### 11.1 为什么不是 `IMAGE_MIRROR_EN=1`

- 顶层参数 `IMAGE_MIRROR_EN=1` 时，表里的 localparam 会变成 `4'h0`（`0x3821=0x00`）；
- `0x00` 会同时把 **H binning 关掉**（bit0=0），800×480 依赖 H binning，分辨率会坏；
- 而且当前 `rom[212]` 已经被写成**字面量 `0x3821_01`**，改顶层参数也不会生效。

### 11.2 `0x3821` 的位

- bit0：H binning（800×480 必须为 1）
- bit1：sensor mirror（会改 Bayer 相位）
- bit2：ISP mirror（只翻图像，不改 Bayer）

### 11.3 本次修改

- `0x3821=0x05`：H binning on + ISP mirror on，sensor mirror off；
- 图像左右翻转，Bayer 相位保持 `0x01` 的（颜色不变）。

### 11.4 如果方向仍不对

- 再试 `0x03`（sensor mirror only）：图像翻，但 Bayer 变（颜色可能又错）；
- 或 `0x07`（both）：图像不翻，Bayer 变；
- 必要时在显示端/顶层做水平翻转。

### 11.5 更正：`0x05` 会破坏 Bayer（红蓝条纹）

- `0x3821` 的 bit2（ISP mirror）和 bit1（sensor mirror）**不是“只翻图像”**，它们和 Bayer/H binning 是耦合的；
- 只开其中一个（`0x05` 或 `0x03`）+ H binning → 图像翻 + **Bayer 错位** → R/B 交换/红蓝条纹；
- 厂家“不镜像”用的是 **`0x07`**（两个 mirror 都开，net 不翻）；本项目颜色修正是 **`0x01`**（两个都关，net 也不翻）；两者都是“无净翻转”，区别在 Bayer 相位；
- 所以**不能用单边 mirror 翻图像**；图像左右应在**显示端**做（`disp_driver`/`rd_ddr3_fifo` 的 H 反向）；
- 当前已回退 `0x3821=0x01`。

### 11.6 应用指南 4.6：镜像和翻转（2026-10-25 查证）

应用指南 `OV5640_自动对焦照相模组应用指南(DVP_接口)__R2.13C.pdf` 第 4.6 节（p28–29）：

- OV5640 是 **BSI 图像传感器**，成像光线从芯片背面射入，**原始图像左右相反**；
- 所以指南把 **MIRROR（镜像）标为默认**，用来把左右纠正过来；
- 官方写法用的是 **0x06（bit2+bit1 一起）**，不是单边：

| 模式 | 0x3820 | 0x3821 |
|---|---|---|
| MIRROR（默认） | `&= 0xf9`（flip off） | `\|= 0x06`（mirror on） |
| FLIP | `\|= 0x06`（flip on） | `&= 0xf9`（mirror off） |
| MIRROR&FLIP | `\|= 0x06` | `\|= 0x06` |
| NORMAL | `&= 0xf9` | `&= 0xf9` |

本项目实测（见第 4、5 节）：

- `0x3821=0x07`（指南 MIRROR）→ **红/绿/蓝映射错**（G 主导）；
- `0x3821=0x01`（指南 NORMAL）→ **颜色正确**；
- 两者都是“net 不翻”，区别在 Bayer 相位；单轴镜像会交换 Bayer 的 R/B，**180° 旋转**才保持 Bayer。

结论：

- 本模组需要 `0x01` 的 Bayer 相位；**指南的 MIRROR（0x07）会把颜色改错**，不能用它来翻左右；
- 指南的 MIRROR 是**参考模组**的默认方向，不代表本模组；
- 若图像只是左右反、上下正常 → 传感器单轴镜像必然改 Bayer，左右只能在**显示端**翻；
- 若图像其实也上下反（180°）→ 可试指南的 **MIRROR&FLIP**（`0x3820=0x46`、`0x3821=0x07`），180° 旋转保持 Bayer；
- 已回退 `0x3821=0x01`。
